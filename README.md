# FuzzyLR3 / Нечёткая система логического вывода

Оболочка нечёткой системы логического вывода на Python (ядро - numpy;
статические графики для отчёта - matplotlib; интерактивная веб-оболочка -
Streamlit + Plotly). Предметная область продолжает **подбор комплектующих
для ПК** из ЛР №1/№2: по тем же входным признакам система теперь выдаёт не
чёткий вывод, а **степень принадлежности** итогового класса сборки нечётким
термам, с дефазификацией в чёткую оценку методом центра тяжести.

Лабораторная работа №3 по дисциплине «Системы искусственного интеллекта»
([LR3Description.md](LR3Description.md)).

## Возможности

- Функции принадлежности: треугольные и трапециевидные (включая термы-«плечи»).
- Нечёткие множества и свод правил хранятся **отдельно от программы**, в
  текстовом JSON-файле (`rules/*.json`), как и в ЛР №1/№2.
- Четыре импликации: Мамдани (min), Ларсен (произведение), Лукасевич, Заде.
- Четыре оператора агрегации: max, min, вероятностная сумма, ограниченная сумма.
  По умолчанию правила объединяются max для Мамдани и Ларсена и min для
  Лукасевича и Заде.
- **Полный композиционный механизм вывода (CRI)** для систем с одним входом:
  строит нечёткое отношение `R(x, y)` по своду правил и находит выход
  max-min или max-произведение композицией со входным (в т.ч. нечётким)
  множеством.
- **Механизм на основе уровней истинности предпосылок правил** (прямой
  алгоритм Мамдани): работает для систем с произвольным числом входов,
  чётких и нечётких, не требует построения многомерного отношения. Для
  нечёткого входа `α_k = sup_x min(A'(x), A_k(x))`.
- Дефазификация методом центра тяжести (центроида).
- 61 unit-тест (pytest), включая перекрёстную проверку: для чёткого входа
  композиционный и прямой механизмы математически обязаны совпадать при
  любой импликации, а для нечёткого - в паре Мамдани+max-min, и совпадают.
- **Интерактивная графическая оболочка** (`app.py`, Streamlit + Plotly):
  выбор базы правил, импликации, агрегации и входных значений на лету;
  2D-графики термов и выходных множеств; **3D**-поверхность нечёткого
  отношения `R(x, y)` (для систем с одним входом) или среза выхода по
  любой паре входов (для систем с несколькими); представление
  **N-мерной** зависимости - параллельные координаты по всему пространству
  входов и локальные срезы чувствительности по каждому входу.

## Быстрый старт

Нужен [uv](https://docs.astral.sh/uv/).

```bash
uv sync                               # установить зависимости
uv run pytest                         # прогнать тесты ядра
uv run python scripts/run_single_input.py   # п.2: 1 вход, 3 механизма x 4 импликации
uv run python scripts/run_multi_input.py    # п.3: 5 входов, уровни истинности x 4 импликации
uv run streamlit run app.py                 # интерактивная графическая оболочка (2D/3D/nD)
```

Скрипты печатают таблицы сравнения в консоль и сохраняют графики/CSV в `output/`.
Веб-оболочка открывается в браузере на `http://localhost:8501`.

### Веб-оболочка (`app.py`)

Боковая панель: выбор файла базы правил из `rules/` (или загрузка своего
JSON), плотность сетки дискретизации, импликация, оператор агрегации,
ползунки для каждой входной переменной (и для систем с одним входом -
переключатель «нечёткий вход»). Вкладки:

- **Термы** - функции принадлежности всех переменных с отметкой текущего
  значения.
- **Вывод** - выходное нечёткое множество и дефазифицированное значение;
  для систем с несколькими входами - ещё и степени истинности предпосылок
  каждого правила (α); сравнение по всем 4 импликациям обновляется live.
- **3D** - поверхность `R(x, y)` для систем с одним входом, либо
  поверхность выхода по любой выбранной паре входов (остальные входы
  зафиксированы ползунками) для систем с несколькими.
- **nD** - локальная чувствительность выхода к каждому входу по
  отдельности (срез при текущих остальных значениях) и параллельные
  координаты по случайной выборке всего пространства входов - способ
  увидеть зависимость сразу от всех N входов одновременно.

## Задача (п.2): 1 вход, 1 выход

`rules/single_input.json`: вход **Бюджет** (₽, 7 термов - нечётких чисел от
«0 ₽» до «210000 ₽» с шагом 35 000 ₽), выход **Класс сборки** (индекс 0..12,
7 термов от «Очень низкий» до «Очень высокий») - 7 правил вида
«ЕСЛИ Бюджет=105000 ₽ ТО Класс сборки=Средний». Терм «105000 ₽» означает
«около 105 000 ₽»: степень принадлежности равна 1 ровно в этой точке и линейно
падает до 0 у соседних термов.

`scripts/run_single_input.py` находит выход для чёткого входа (92 000 ₽) и
нечёткого входа («около 150 000 ₽», треугольник ±20 000 ₽) тремя
механизмами - CRI max-min, CRI max-произведение, уровни истинности - для
всех 4 импликаций, и строит развёртку выхода по диапазону центра нечёткого
бюджета. При чётком входе все три механизма совпадают математически (срез
`R(x0, y)`), различия в третьем знаке вызваны привязкой к узлу сетки.
Различаются они на нечётком входе:

| Импликация | max-min | max-произв. | Уровни истинности |
| --- | --- | --- | --- |
| Мамдани | 8.491 | 8.594 | 8.491 |
| Ларсен | 8.499 | 8.497 | 8.494 |
| Лукасевич | 6.375 | 6.544 | 6.770 |
| Заде | 6.183 | 6.327 | 6.515 |

## Задача (п.3): 5 входов, 1 выход

`rules/multi_input.json`: пять входных переменных - **Бюджет** (термы «65000 ₽»,
«80000 ₽», «135000 ₽» - те же бюджеты, что в базе правил ЛР №1/2),
**Требовательность задач**, **Важность видеокарты** (по 3 терма), плюс два новых
непрерывных признака из предметной области ЛР №1/2 - **Разрешение монитора**
(млн пикселей кадра: 1080p/1440p/4K) и **Желаемая компактность корпуса**
(континуальный аналог бинарного «Форм-фактор»). В отличие от моделей
конкретных комплектующих (CPU/материнская плата и т.п.) - категориальных
значений без естественной шкалы - оба новых признака действительно непрерывны,
поэтому им можно задать функции принадлежности. Выход - та же переменная
**Класс сборки**, что и в однофакторной системе (для сопоставимости).

32 правила: плотная таблица из **27 правил**, покрывающая все 3×3×3 комбинации
трёх основных входов (вес в сумме: Бюджет ×3, Требовательность ×1, Важность
видеокарты ×1 → линейно на 7 выходных термов), плюс **5 корректирующих
правил** для разрешения и компактности. Каждое корректирующее правило
обязательно включает условие на Бюджет - иначе оно срабатывает независимо от
бюджета и тянет результат в сторону, не учитывающую реальную платёжеспособность
(на это натолкнулись при разработке: правило «1080p И низкая важность
видеокарты → Низкий» без привязки к бюджету задирало вниз сценарий с высоким
бюджетом и лёгкими задачами просто потому, что видеокарта была не важна -
после добавления условия «И Бюджет=65000 ₽» это ушло).

`scripts/run_multi_input.py` прогоняет 9 представительных сценариев через
механизм уровней истинности для всех 4 импликаций и строит две тепловые
карты: выход по «Бюджет × Требовательность задач» (остальное фиксировано на
средних значениях) и выход по «Разрешение монитора × Компактность корпуса»
(остальное фиксировано на значениях, уверенно активирующих корректирующие
правила - см. комментарий в скрипте про вырождение степеней истинности
ровно на границах термов).

## Сравнение импликаций (п.4) - ключевой вывод

Мамдани и Ларсен дают содержательный, монотонный, хорошо различимый выход.
Это конъюнктивные правила: не сработавшее правило даёт 0, поэтому правила
объединяются через `max`.

**Лукасевич и Заде** - логические импликации со свойством `I(0, b) = 1`: не
сработавшее правило ничего не утверждает. Через `max` такие правила заливают
результат единицами, и выход равен 6.0 при любом входе, поэтому объединять их
нужно через `min`. Вероятностная и ограниченная суммы этого не исправляют.

С `min` выход зависит от входа, но ведёт себя иначе, чем у Мамдани:

- При частичном срабатывании у `B'(y)` остаётся ненулевой уровень `1 - α`,
  который тянет центр тяжести к середине универсума. Поэтому выход сжат к 6 и
  не монотонен: совпадает с Мамдани на вершинах термов (при 70 000 ₽ у всех
  4.0), а между ними уходит к центру (при 52 500 ₽ Мамдани 3.0, Лукасевич 5.77,
  Заде 6.0). Система с пятью входами на случайных входах даёт 2.59..9.57 у
  Лукасевича и 2.62..9.49 у Заде против 1.37..11.16 у Мамдани.
- Правила, которые одновременно истинны и имеют непересекающиеся следствия,
  прямо противоречат друг другу, и `B'(y)` становится пустым. У системы с пятью
  входами это углы пространства (например, бюджет 0, все признаки 0 и монитор
  4K - правила #1 и #29). Центр тяжести тогда формально равен 6.0, а оболочка
  показывает предупреждение. На 3000 случайных входах пустых множеств не было,
  но высота `B'(y)` опускалась до 0.13: там правила сильно расходятся.

Для такой базы правил, составленной в логике «правило описывает точку», лучше
подходят Мамдани и Ларсен. Графики - `output/single_input_sweep.png` и
`output/multi_input_heatmap.png`.

### Формат файла базы правил

```json
{
  "variables": {
    "Бюджет": {
      "universe": [0, 210000],
      "terms": { "105000 ₽": { "type": "triangular", "points": [70000, 105000, 140000] } }
    },
    "Класс сборки": {
      "universe": [0, 12],
      "terms": { "Средний": { "type": "trapezoidal", "points": [4, 6, 6, 8] } }
    }
  },
  "input_vars": ["Бюджет"],
  "output_var": "Класс сборки",
  "rules": [{ "if": { "Бюджет": "105000 ₽" }, "then": "Средний" }]
}
```

`type` - `"triangular"` (3 точки `[a, b, c]`) или `"trapezoidal"` (4 точки
`[a, b, c, d]`). Минимум 7 правил; все переменные и термы, упомянутые в
правилах, проверяются при загрузке.
